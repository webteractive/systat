# systat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build systat, a macOS menu bar app whose gauge icon turns red when
memory, CPU or disk is critical, and whose panel lists the top 10 memory or
CPU processes with Quit and Force Quit.

**Architecture:** A Swift package with two targets. `SystatCore` is a library
of pure logic: limit rules, naming, protection, process folding, list
stability and formatting, all unit-tested with fake samples. `systat` is the
executable. It reads the system (sysctl, Mach host statistics, libproc,
`/bin/ps`), sends signals, and draws the UI: an `NSStatusItem` with an
`NSPopover` that hosts SwiftUI views. `scripts/install-local.sh` assembles an
ad-hoc signed `.app` from the release build and installs it.

**Tech Stack:** Swift 6.3 (tools version 6.2), SwiftPM, SwiftUI + AppKit,
Swift Testing (`import Testing`), ServiceManagement. No third-party packages.

**Spec:** `docs/superpowers/specs/2026-11-05-systat-design.md`. Read it before
any task. Where this plan and the spec disagree, the spec wins; stop and say
so.

## Global Constraints

- macOS 26 on Apple silicon only: `platforms: [.macOS(.v26)]`, build `--arch arm64`.
- Swift 6 language mode with strict concurrency; Core types are `Sendable`.
- No third-party dependencies.
- No Dock icon: `LSUIElement` = `true` in `Resources/Info.plist`, and `NSApp.setActivationPolicy(.accessory)`.
- Not sandboxed. Ad-hoc signed only (`codesign --sign -`), installed to `/Applications/systat.app`. The install script says the build is local and not for distribution.
- Bundle identifier `dev.inggo.systat`, version `0.1.0`.
- Critical red is `#C8232C` everywhere it appears (icon, bars, status line, Force Quit).
- Memory and swap display and limits use 2³⁰ bytes per GB; disk uses 10⁹.
- systat budget with the menu closed: under 1% CPU on average, about 60 MB of memory.
- Clean build output when a build is done: the install script removes `.build/` and its staging folder; the final task removes `.build/`.
- Signals go to the exact PID shown, after checking its start time still matches.
- Commit messages carry no `Co-Authored-By` line.

## Review Focus

1. **Sleep and wake.** A Mac that slept during a CPU-heavy spell must not come back with a red icon after one busy sample. The CPU hold resets when samples are more than 15 s apart (Task 2 test `cpuHoldResetsAfterSampleGap`).
2. **Odd process names from `ps`.** Names with spaces and parentheses (`Google Chrome Helper (Renderer)`) and a non-English locale's decimal comma must not corrupt the list. `ps` runs with `LC_ALL=C` and the command is the rest of the line (Task 6 test `parsesCommandWithSpacesAndParens`).
3. **PID reuse under a frozen list.** A process that exits while its PID is taken by a new one must show "Ended", not take over the row, so Force Quit cannot hit the newcomer (Task 5 test `reusedPIDIsEndedNotAdopted`).
4. **A `claude` started from inside another `claude`** (via its Bash tool) must fold into the outer session, not get its own row or be counted twice (Task 4 test `nestedClaudeFoldsIntoOutermost`).
5. **`claude` argument edge cases:** `--resume=<id>`, `-r` followed by another flag, `-n` with no value, both `-n` and `-r` given (Task 3 test `claudeLabelEdgeCases`).

Rules the tests imply: memory under 1 MiB is `<1 MB`, under 1 GiB is whole
MB (MiB), otherwise GB (GiB) with one decimal. Bar-detail GB numbers use one
decimal and drop a trailing `.0` (`8`, not `8.0`). Disk free under 10 GB gets
one decimal, otherwise whole. CPU and load round half up. Age is `nil` unless
more than 86 400 s; days are floored. `updated` floors seconds under 60, then
whole minutes. Approximate values are prefixed `≈ ` (with a space).

  ```swift
  public struct CPUTicks: Sendable, Equatable { public var user, system, idle, nice: UInt64 }
  extension CPUTicks { public static func busyFraction(from: CPUTicks, to: CPUTicks) -> Double } // 0...1; 0 if no ticks elapsed
  public struct MachineSample: Sendable, Equatable {
    public var time: Date
    public var pressureLevel: Int32      // 1 normal, 2 warning, 4 critical
    public var swapUsed, swapTotal: UInt64
    public var memoryUsed, memoryTotal: UInt64
    public var cpuBusy: Double           // 0...1
    public var load1: Double
    public var diskFree, diskCapacity: UInt64

  public struct Limits: Sendable {
    public var swapBytes: UInt64 = 4 * Units.gib
    public var cpuBusy: Double = 0.85
    public var cpuHold: TimeInterval = 30
    public var diskCritical: UInt64 = 15 * Units.gb
    public var diskClear: UInt64 = 16 * Units.gb
    public var maxSampleGap: TimeInterval = 15
    public static let standard = Limits()
  }
  public struct CriticalState: Sendable, Equatable {
    public var memory = false, cpu = false, disk = false
    public var count: Int { get }; public var any: Bool { get }
  }
  public struct CriticalEvaluator: Sendable {
    public init(limits: Limits = .standard)
    public private(set) var state: CriticalState
    public mutating func update(_ sample: MachineSample) -> CriticalState
  }
  public enum ListKind: Sendable, Hashable, CaseIterable { case memory, cpu }
  public func initialList(for state: CriticalState) -> ListKind
  ```

- [ ] **Step 3: Implement `Machine.swift` and `Critical.swift`**

Memory: `pressure >= 4 || (swapUsed > limits.swapBytes && pressure >= 2)`.
Disk: `free < (state.disk ? diskClear : diskCritical)`. CPU hold, which the
signatures don't determine:

```
if let last = lastTime, sample.time - last > maxSampleGap { cpu = false; aboveSince = nil; belowSince = nil }
if sample.cpuBusy > limits.cpuBusy {
  belowSince = nil; aboveSince = aboveSince ?? sample.time
  if !cpu && sample.time - aboveSince! >= cpuHold { cpu = true }
} else {
  aboveSince = nil; belowSince = belowSince ?? sample.time
  if cpu && sample.time - belowSince! >= cpuHold { cpu = false }
}
lastTime = sample.time
```

- [ ] **Step 3: Implement the three files**

- `displayName`: `app?.name`, else basename of `arguments?.first`, else basename of `executablePath`, else `commandName`.
- `isClaude`: `app == nil && displayName == "claude"`.
- `claudeLabel` precedence: name (`-n`/`--name <v>`, `--name=v`) > resume id (`-r`/`--resume <v>`, `--resume=v`; first 8 characters, prefixed `session `) > bare resume (`-r`/`--resume` with no value, or `-c`/`--continue`: `resumed · <folder>`, or `resumed` with no folder) > folder > `pid <n>`. A value is the next argument when it exists and does not start with `-`. Folder is the last path component of the working directory; `/` or `nil` gives no folder.
- `detail` order: claude label (claude rows only, never the path rule) → if `nameIsShared` and the executable is outside the standard places, the folder holding the `.app` (apps) or the executable (others) → `wellKnown[name]` → an app's bundle folder → the executable's folder → `pid <n>`. Then append ` · <age>` when `Format.age` gives one. Standard places: path prefixes `/Applications/`, `/System/`, `/usr/`, `/bin/`, `/sbin/`, `/Library/`, `<home>/Applications/`. Paths under `home` are shown with `~`.
- `wellKnown`: at least `fseventsd` "File change tracker", `WindowServer` "Display server", `airportd` "Wi-Fi daemon", `kernel_task` "macOS kernel", `launchd` "Service manager", `mds` "Spotlight", `mds_stores` "Spotlight index", `mdworker_shared` "Spotlight indexer", `coreaudiod` "Audio", `bluetoothd` "Bluetooth", `cloudd` "iCloud sync", `backupd` "Time Machine", `photoanalysisd` "Photos analysis", `loginwindow` "Login session", `Dock` "Dock", `Finder` "Finder", `softwareupdated` "Software Update".
